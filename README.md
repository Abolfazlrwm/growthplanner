# GrowthPlanner — یک فضای آرام برای رشد روزانه

یک برنامهٔ وب فارسی/انگلیسی برای اتصال هدف‌های بزرگ به کارهای کوچک روزانه؛ ساخته‌شده بر پایهٔ پروژهٔ اصلی Django + DRF + HTMX. این ارتقا معماری موجود را حفظ می‌کند و یک فرانت‌اند جدا و غیرضروری به آن تحمیل نمی‌کند.

## امکانات این نسخه

داشبورد «امروز» با عملکرد هفت روز اخیر، دقیقه‌های تمرکز، عادت‌های فعال، وضعیت روزهای هفته و پیشرفت هدف‌ها به دادهٔ واقعی حساب متصل است. نمای دسکتاپ دارای ناوبری فضای کار و نمای موبایل واکنش‌گراست. زبان فارسی با RTL و تاریخ شمسی، انگلیسی با LTR، حالت روشن/تاریک/خودکار و هشت پالت رنگ حفظ شده‌اند.

مدیریت تسک شامل اولویت، موعد و ساعت، وضعیت، دلیل انجام‌نشدن، جستجو، برد فیلترشونده، برچسب خصوصی و زیرتسک قابل تکمیل است. هدف‌ها موعد، وضعیت و پیشرفت دارند و اکنون نقاط عطف تاریخ‌دار و قابل تکمیل نیز دارند. تقویم ماه، هفته با جابه‌جایی، خط زمان روز، عادت‌ها، پومودورو، دفتر روزانه و گزارش‌های قبلی حفظ شده‌اند.

### افزودن با جملهٔ طبیعی

در `/tasks/smart/` بنویس:

```text
فردا ساعت ۹ مطالعه برای ۳۰ دقیقه #یادگیری با اولویت بالا
هر روز ساعت ۸ ورزش برای ۴۵ دقیقه
شنبه آینده ساعت ۱۰ جلسه پروژه #رزومه
2026-11-03 at 14:30 review portfolio for 45 minutes high priority #work
```

تحلیل **قاعده‌محور و بدون فراخوانی AI** است؛ ارقام فارسی/عربی، تاریخ میلادی ISO و تاریخ عددی شمسی، روزهای هفته، ساعت، مدت، اولویت، هشتگ و تکرار روزانه/هفتگی را پوشش می‌دهد. نتیجه پیش از ذخیره قابل اصلاح است. هشدار ابهام باید تأیید شود؛ جملات خارج از الگو نیاز به اصلاح دستی دارند. این قابلیت تشخیص آزاد و بی‌نقص هر جمله نیست.

تکرار، یک قالب `Habit` می‌سازد و از تاریخ انتخاب‌شده شروع می‌شود. اولویت و برچسب‌ها در رخدادهای بعدی نیز حفظ می‌شوند. رخدادهای واقعی هنگام مشاهدهٔ روز/بازه به‌صورت محدود ساخته می‌شوند؛ فید تقویم رخدادهای آینده را فقط در حافظه نمایش می‌دهد. تغییر عادت، رخدادهای ناتمام آیندهٔ همان عادت را هماهنگ می‌کند؛ تاریخچه و رخدادهای تکمیل‌شده دست‌نخورده می‌مانند.

### فید اشتراک تقویم

در `/calendar/subscription/` لینک اختصاصی حساب را کپی کن. لینک به اشتراک iCalendar در تقویم‌های سازگار متصل می‌شود، نه ورود OAuth و همگام‌سازی دوطرفه با Google Calendar.

توکن تصادفی، تاریخ انقضا، ساخت لینک تازه و ابطال فوری دارد. هر دارندهٔ لینک می‌تواند عنوان تسک‌ها را بخواند؛ آن را خصوصی نگه دار. محدوده ۳۰ روز گذشته تا ۳۶۵ روز آینده و حداکثر ۱٬۰۰۰ رویداد است. زمان‌های ساعت‌دار به UTC با مبدأ تهران تبدیل می‌شوند و encoding/folding فارسی مطابق iCalendar است. خروجی دانلودی قدیمی `/tasks/export.ics` نیز حفظ شده است.

### همراه هوشمند واقعی

در `/assistant/` برای برنامه‌ریزی روز، اولویت‌بندی، شکستن هدف و مرور هفته گفت‌وگو کن. فراخوانی مدل فقط در سرور انجام می‌شود. مدل پیش‌فرض محیط مدیریت‌شده `gpt-6-luna` و متغیر اختیاری `AI_MODEL` است؛ بیرون این محیط باید مدل واقعاً موجودِ ارائه‌دهندهٔ خودت را انتخاب کنی.

فرستادن اطلاعات برنامه تنها با رضایت checkbox است: حداکثر ۴۰ تسک باز، ۸ هدف فعال و جمع‌بندی عددی هفت روز اخیر. دفتر روزانه خودکار ارسال نمی‌شود. پیشنهادها ابتدا اعتبارسنجی و ذخیرهٔ موقت می‌شوند و فقط با تأیید تو به تسک تبدیل می‌شوند. ایجاد پیشنهاد تأییدشده idempotent است؛ دستیار خودکار چیزی حذف یا ویرایش نمی‌کند. محدودیت پیش‌فرض ۱۲ درخواست در ساعت به‌ازای حساب در دیتابیس ثبت می‌شود. نبود سرویس، timeout و خروجی نامعتبر خطای قابل بازیابی دارند، نه پاسخ نمایشی.

### حساب و داده

ثبت‌نام/ورود/خروج، ویرایش پروفایل، تغییر رمز، حذف حساب با تأیید و خروجی JSON نسخهٔ `2.0` وجود دارد. خروجی هدف، تسک، عادت، یادداشت، تمرکز، برچسب‌ها و روابط، زیرتسک، نقاط عطف و سابقهٔ دستیار را شامل می‌شود؛ رمز، کلید API و توکن فید صادر نمی‌شوند. ابزار import/restore JSON هنوز پیاده‌سازی نشده است.

**بازیابی ایمیل در انتشار بدون SMTP غیرفعال است.** backend کنسول برای توسعه است و به معنی ارسال ایمیل نیست. ایمیل اختیاری پروفایل هنوز تأیید مالکیت ندارد.

## فناوری و ساختار

Python 3.12 · Django 5.2.18 LTS · DRF · HTMX 2 · WhiteNoise · Gunicorn · jdatetime · drf-spectacular. دیتابیس مدیریت‌شده MySQL سازگار است؛ PostgreSQL و SQLite محلی نیز پشتیبانی می‌شوند. شاخهٔ Django 5.2 به‌دلیل سازگاری با MySQL 8.0 محیط انتخاب شده است.

```text
apps/accounts/      احراز هویت، پروفایل و خروجی داده
apps/core/          داشبورد، تمرکز، گزارش، امنیت و ترجمه
apps/tasks/         تسک، زیرتسک، برچسب، تحلیل جمله و ICS
apps/goals/         هدف و نقطهٔ عطف
apps/habits/        قالب تکرار، تولید محدود و همگام‌سازی آینده
apps/journal/       دفتر و حال‌وهوا
apps/calendar_view/ تقویم و اشتراک امن iCalendar
apps/assistant/     گفتگو، سرویس مدل و پیشنهاد قابل تأیید
config/db/          backend MySQL با ALTERهای جداگانهٔ ستون و FK
config/            تنظیمات و مسیرهای وب/API
utils/             تاریخ جلالی/میلادی
scripts/           تولید فهرست مسیرهای واقعی وب
static/            CSS، JavaScript، لوگو و PWA
```

## اجرای محلی

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# SECRET_KEY را در .env با یک مقدار تصادفی واقعی جایگزین کن.
python manage.py migrate
python manage.py runserver
```

آدرس محلی: `http://127.0.0.1:8000`. در نبود `DATABASE_URL`، SQLite محلی استفاده می‌شود. `.env` و دیتابیس شخصی را هرگز commit نکن.

## استقرار

Dockerfile وابستگی‌های pinned و static manifest را بدون نیاز به کلیدها و دیتابیس زمان اجرا می‌سازد. `entrypoint.sh` روی `PORT` یا پیش‌فرض ۳۰۰۰ اجرا می‌شود. مهاجرت باید **یک بار پیش از release** اجرا شود؛ start مکرر کانتینر migration یا seed خودکار انجام نمی‌دهد.

```bash
python manage.py migrate --noinput
python manage.py collectstatic --noinput  # استقرار بدون Docker
sh entrypoint.sh
```

در Manus دیتابیس و کلیدهای سرویس در runtime تزریق می‌شوند. خارج از آن، `SECRET_KEY` تصادفی، `DEBUG=False`، `DATABASE_URL` پایدار، `ALLOWED_HOSTS` دقیق، `CSRF_TRUSTED_ORIGINS` و HTTPS را تنظیم کن. برای canonical و تصویر اجتماعی، `PUBLIC_ORIGIN` باید دامنهٔ عمومی واقعی باشد؛ از Host داخلی پراکسی برای ساخت لینک مرورگر استفاده نمی‌شود. بازیابی ایمیل نیاز به تنظیم `EMAIL_*` دارد.

کوکی‌های محیط HTTPS تعبیه‌شده `SameSite=None; Secure` هستند. سیاست مرورگر دربارهٔ third-party cookies ممکن است ورود در iframe را محدود کند. MySQL این محیط CHECKهای قدیمی را enforce نمی‌کند؛ فرم‌ها و serializerها قواعد را بررسی می‌کنند. نوشتن مستقیم SQL یا bulk script باید همان قواعد را رعایت کند.

## API برای فاز موبایل

مستندات احراز هویت‌شده: `/api/docs/`، schema: `/api/schema/`.

- `/api/goals/`، `/api/tasks/`، `/api/habits/`، `/api/notes/`: CRUD مالکیتی با pagination.
- `POST /api/token/`: نام کاربری و رمز؛ سپس `Authorization: Token ...`.
- پیشنهادهای AI فعلاً endpointهای session-based وب هستند؛ OAuth/PKCE، endpointهای کامل منابع جدید و مدیریت چرخهٔ توکن موبایل باید در فاز اپ طراحی شوند.

این نسخه **اپ بومی نیست**. PWA نصب می‌شود و آفلاین fallback امن دارد؛ ویرایش آفلاین و همگام‌سازی پس از اتصال هنوز پیاده‌سازی نشده‌اند.

## بررسی و تست

آزمون‌ها را فقط با دیتابیس موقت اجرا کن؛ دیتابیس مدیریت‌شده بین توسعه و انتشار مشترک است.

```bash
SECRET_KEY=test-only DEBUG=True DATABASE_URL=sqlite:////tmp/growthplanner-tests.sqlite3 \
  python manage.py test --noinput
python manage.py makemigrations --check --dry-run
python manage.py check
python manage.py spectacular --file /tmp/openapi.yml --validate
node --check static/js/assistant.js
```

CI شامل تست، migration drift، collectstatic و Docker build است. گزارش بررسی و شواهد این ارتقا در `docs/upgrade-audit-fa.md` ثبت شده‌اند.

## مرحلهٔ بعد، نه ادعای امکانات فعلی

اولویت‌های بعدی برای محصول عمومی بزرگ: SMTP و تأیید ایمیل، throttling مشترک پایدار ورود در چند replica، سیاست حریم خصوصی/شرایط استفاده، مشاهده‌پذیری و backup/restore آزمایش‌شده، pagination برد بسیار بزرگ، استثناهای تکرار، یادآوری Push و صف کار، و سپس API موبایل و اپ بومی. ابزارهای اجتماعی، پرداخت، همکاری تیمی و اعلان خودکار فعلاً وجود ندارند.
